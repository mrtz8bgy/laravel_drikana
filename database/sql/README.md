# راهنمای ارتقای دیتابیس

این پوشه شامل فایل SQL ارتقای دیتابیس پروژه دریکانا است.

## فایل‌ها

| فایل | توضیح |
|------|-------|
| `platform_upgrade.sql` | فایل اصلی ارتقا — جداول جدید، ستون‌های تازه و داده اولیه نقش‌ها و مجوزها |

---

## پیش از اجرا

> **مهم:** همیشه پیش از اجرا از دیتابیس خود پشتیبان بگیرید.

```bash
mysqldump -u USER -p DBNAME > backup_before_upgrade.sql
```

نکته: برای بازیابی، همین فایل را روی یک دیتابیس خالی ایمپورت کنید:

```bash
mysql -u USER -p -e "CREATE DATABASE DBNAME CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
mysql -u USER -p DBNAME < backup_before_upgrade.sql
```

## اجرای ارتقا

### روش ۱ — از طریق خط فرمان

```bash
mysql -u USER -p DBNAME < database/sql/platform_upgrade.sql
```

### روش ۲ — داخل کلاینت mysql

```sql
USE DBNAME;
SOURCE /مسیر/کامل/به/database/sql/platform_upgrade.sql;
```

### روش ۳ — از طریق phpMyAdmin یا Navicat

فایل `platform_upgrade.sql` را باز کنید و روی «Import» بزنید.
اگر ابزار شما از دستور `DELIMITER` پشتیبانی نمی‌کند، از روش ۱ استفاده کنید.

## ویژگی‌های این فایل

| ویژگی | توضیح |
|-------|-------|
| **تکرارپذیر (Idempotent)** | اجرای چندباره آن بی‌خطر است و خطای تکراری‌سازی نمی‌دهد |
| **بدون حذف داده** | هیچ جدول، ستون یا رکوردی حذف نمی‌شود |
| **سازگار با MariaDB و MySQL** | برای `ADD COLUMN IF NOT EXISTS` که فقط در MariaDB هست، از رویه‌های کمکی استفاده می‌کند |
| **بدون کاربر یا رمز** | هیچ کاربری ساخته نمی‌شود و هیچ رمزی تغییر نمی‌کند |
| **حفظ تنظیمات مدیر** | مجوزهایی که بعداً از پنل به نقش‌ها داده‌اید بازنویسی نمی‌شود (`INSERT IGNORE`) |

## پس از اجرا

در انتهای خروجی، سه کوئری بررسی اجرا می‌شود. نتیجه درست:

```
جدول‌های جدید   : ۱۳
نقش‌های سیستمی  : ۶
مجوزها          : ۸۶
انتساب نقش-مجوز : ۱۴۳
```

سپس نخستین **مدیر کل سیستم** را بسازید:

```bash
php artisan drikana:make-super-admin
```

اگر کد پروژه را هم به‌روز کرده‌اید، گام‌های زیر را هم اجرا کنید:

```bash
php artisan migrate --force          # بی‌خطر است؛ روی دیتابیس ارتقایافته تغییری نمی‌دهد
php artisan db:seed --class=RbacSeeder --force
php artisan config:clear
php artisan cache:clear
```

## جایگزین: استفاده از مایگریشن‌های Laravel

اگر ترجیح می‌دهید از خود Laravel استفاده کنید، اجرای این دو دستور همان
نتیجه این فایل را می‌دهد:

```bash
php artisan migrate --force
php artisan db:seed --class=RbacSeeder --force
```

## بازگردانی (Rollback)

این فایل عمداً «یک‌طرفه» است تا داده از دست نرود. برای بازگردانی، از
پشتیبانی که پیش از اجرا گرفته‌اید استفاده کنید. اگر می‌خواهید فقط
مایگریشن‌های Laravel را برگردانید:

```bash
php artisan migrate:rollback --step=6
```

> توجه: rollback ستون‌ها و جداول افزوده‌شده را حذف می‌کند و در نتیجه
> **داده‌های موجود در آن‌ها از دست می‌رود**. روی محیط production فقط با
> پشتیبان کامل انجام دهید.

## ساختار فایل ارتقا

| بخش | محتوا |
|-----|-------|
| بخش ۰ | رویه‌های کمکی برای سازگاری MySQL/MariaDB |
| بخش ۱ | ساخت ۱۳ جدول جدید (RBAC، حسابرسی، مالکیت، مقالات، …) |
| بخش ۲ | افزودن ستون و ایندکس به جداول موجود |
| بخش ۳ | یکپارچه‌سازی نقش‌های قدیمی (تولید `slug` برای رکوردهای موجود) |
| بخش ۴ | درج ۶ نقش، ۸۶ مجوز و ۱۴۳ انتساب نقش-مجوز |
| بخش ۵ | پاک‌سازی رویه‌های موقت |
| بخش ۶ | کوئری‌های بررسی صحت نتیجه |
